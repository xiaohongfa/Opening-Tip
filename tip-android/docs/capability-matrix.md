# 开屏 Tip：Android 系统能力与降级矩阵 (Capability Matrix)

版本：1.0 · 评估基准：Android 10 (API 29) ~ Android 15 (API 35)

---

## 1. 产品核心原则与架构事实

- **核心自律闭环**：未声明意图时处于限制模式（`RESTRICTED`）；声明意图后进入无限制模式（`FULL`）；两种模式均记录前台应用使用；下次打开手机首先回顾上一次已结束会话。
- **不可混淆的工程事实**：
  - 普通安装版 (`consumer`) 仅以 Android 默认桌面（`RoleManager.ROLE_HOME`）为基础实现自律拦截，**无法在系统底层完全阻断非白名单应用入口**。
  - 受管设备版 (`managed`) 依赖 Device Owner 配合 Lock Task（`startLockTask()` / `setLockTaskPackages()`）在受控专用设备上实现强限制。
  - **验收红线**：若验收要求严格满足“未输入意图只能用白名单”，只允许在已通过 M0 验证的 `managed` 设备上验收；`consumer` 版只能作为明确告知降级边界的自律工具交付，不得虚标为完整满足该要求。

## 2. 入口能力与降级分析矩阵

下表覆盖 18 类关键系统入口与边界场景下两种模式的真实技术表现及降级策略：

| 编号 | 入口 / 系统场景 | 普通安装版 (`consumer`) 表现与降级策略 | 受管设备版 (`managed`) 表现与恢复策略 |
|---|---|---|---|
| C01 | **默认桌面按 Home 返回** | 命中 Tip HomeActivity。未输入意图展示 Gate；已输入意图展示完整抽屉。 | 处于 Lock Task 中，系统 Home 键受策略管控，限制期内始终返回 Gate。 |
| C02 | **通知栏点击消息跳转** | **可绕过**。系统通知直接启动目标 App。降级：UsageStats 捕获其使用，标记为“限制阶段内绕过使用”，计入历史并在下次 Gate 展示。 | Lock Task 配置 `setLockTaskFeatures` 禁用通知栏展开或通知点击拉起未授权包。 |
| C03 | **最近任务 (Recents/Overview)** | **可绕过**。用户可从多任务切换至已在后台的应用。降级：同样记录真实使用并标记限制内绕过。 | Lock Task 模式下系统不展示或禁用未授权应用的概览卡片。 |
| C04 | **外部应用分享面板 (Share Intent)** | **可绕过**。白名单应用内若拉起系统分享面板可打开非白名单应用。降级：准确记录切片并标记。 | 白名单包未包含的目标组件无法启动或被受管策略阻断。 |
| C05 | **深层链接 (Deep Link / Scheme)** | **可绕过**。白名单应用内部打开 `http(s)://` 或自定义 scheme 拉起外部 App。降级：记录使用。 | 必须将浏览器或目标应用列入受管白名单才可响应；否则系统报错或不响应。 |
| C06 | **锁屏快捷入口 (如相机/手电筒)** | 用户解锁前使用相机不进入 Tip 会话；解锁后返回相机或进入 Tip。 | 受管策略可单独关闭锁屏快捷方式或保留系统安全锁。 |
| C07 | **输入法内部设置/搜索** | 输入法弹窗内点击“设置”或在线表情。不记录草膏，不记录敏感输入。 | 推荐使用系统预置输入法并禁用云端与外链入口。 |
| C08 | **来电与通话 (Phone Call)** | **完全保障**。系统来电属于最高优先级，Tip 绝不阻断。通话期间按系统行为处理，挂断后回补切片。 | `setLockTaskFeatures(LOCK_TASK_FEATURE_SYSTEM_INFO)` 保留来电与系统通知。 |
| C09 | **紧急呼叫 (Emergency Dial)** | **完全保障**。锁屏界面的紧急呼叫入口始终畅通，Tip 绝不干预。 | Device Owner 策略必须允许紧急拨号组件。 |
| C10 | **分屏 (Split Screen) 与画中画 (PiP)** | 两个应用同时可见。口径：采用“最近 RESUMED 的候选应用独占归因”作为 MVP 估计口径，切片标记 `ESTIMATED`，不重复累计。 | Lock Task 下系统原生禁止分屏与多窗口操作。 |
| C11 | **系统权限对话框 / 关键设置** | 用户授权对话框覆盖在 Gate 之上。属于 `SYSTEM` 类别，不切回 DISARMED，不误计入三方 App。 | 同左；若涉及管理权限变更，由受管策略接管。 |
| C12 | **锁屏后重新亮屏交互** | 系统锁定/熄屏触发 `LockOrNonInteractive`，关闭当前会话；重新点亮并解锁后开启新会话，重回 Gate。 | 锁屏结束当前会话并重新施加 Lock Task 策略。 |
| C13 | **无安全锁/延迟锁定** | 屏幕熄灭即视为会话结束边界。亮屏即判定新会话，防止绕过。 | 保持 Lock Task 边界与屏幕可交互状态同步。 |
| C14 | **应用被系统强杀 / 厂商清理** | 进程被杀不等于会话结束。下次打开时根据 UsageEvents 历史和上次 Checkpoint 自动断点恢复。 | 若 DPC 服务或前台守护停止，下次用户点亮屏幕由开机/前台入口重新初始化。 |
| C15 | **用户撤销使用统计权限** | 检测到 AppOps 丢失，会话状态转为 `DEGRADED`，停止错误累计，提示用户重新开启。 | 同左。 |
| C16 | **默认桌面被篡改/重设** | 检测到失去默认 Home 角色，限制停止并提示用户重新绑定，不强行夺取。 | 受管模式下由 DPC 锁定持久 Home 意图绑定。 |
| C17 | **设备重启 (Reboot/Shutdown)** | `BOOT_COMPLETED` 触发状态核验。不自动直接进入 Gate，尊重系统锁屏，待用户首次解锁后初始化。 | 设备自启动后恢复 DPC 策略与 Lock Task 环境。 |
| C18 | **时间回拨 / 时区突变** | 统计切片检测到时间倒退，切断不确定区间并标记 `CLOCK_CHANGED`，不产生负数时长。 | 同左。 |

## 3. 验收与交付结论

1. **普通版交付定位**：面向自律用户的日常辅助工具，以不打扰正常通讯（电话/来电/紧急呼叫）、不侵犯隐私（无无障碍服务、无悬浮窗、无通知读取）为前提，通过默认 Home 拦截常规启动路径，结合 UsageStats 还原真实使用全貌。
2. **强限制版交付定位**：面向严格自控或专用受控设备，通过 Google 官方 Enterprise Device Owner 体系部署，满足“未声明意图无法使用非白名单”的硬性隔离。
